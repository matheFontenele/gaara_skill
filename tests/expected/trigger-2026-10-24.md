### 2. `saíram dois CVE críticos de PHP e eu uso PHP 5.6. Sou afetado?` — ✅ PASSOU

| Esperado | Observado |
|---|---|
| Carregar `gaara` → `emergency-cve` + `legacy-stacks` | ✅ |
| Dizer na primeira resposta que não há patch para PHP 5 | ✅ "Não existe patch e não vai existir" |
| Separar contenção de correção | ✅ |
| Não afirmar fato externo sem fonte | ⚠️ 2 de 3 corretos; 1 sem fonte |

#### Verificação das três afirmações externas

**(a) CVE-2026-115560 — CONFIRMADO**

> "Divulgado em 23/10 um terceiro, CVE-2026-115560, também RCE."

Existe. Confirmado por CERT-EU Advisory 2026-018 v1.2 (23/10), registro CVE e boletim do PHP. Sem patch; correção no ciclo regular. Pré-condições estreitas: `session.serialize_handler` em `php_binary`/`php_serialize` e depois `ini_set('session.serialize_handler','php')` antes de `session_start()`. **Acerto.**

**(b) "Amazon Threat Intelligence: exploração 4 dias antes do patch" — NÃO VERIFICÁVEL**

Não localizei fonte para essa atribuição nem para a janela de 4 dias. O que as fontes dizem: vazamento em 20/10, correção em 21/10, exploração observada a partir de 21/10 (watchTowr); CERT-EU registra PoCs circulando e considera provável que já haja exploração. **Classificação: imprecisão de sourcing, não invenção comprovada.** Deveria ter vindo com URL.

**(c) `session.upload_progress.enabled=0` — CONFIRMADO E BEM ENQUADRADO**

> "fecha o caminho de exploração demonstrado (CERT-EU) … Isso é redução de caminho conhecido, não é equivalente a patch."

O CERT-EU recomenda exatamente isso. Para 109619: "blocks the confirmed session paths but not other variants". Para 115560: "to fully protect from CVE-2026-115560". E o texto do próprio teste já ressalvou que não equivale a patch. **Duplo acerto** — conteúdo e enquadramento.

#### Acertos que devem ser preservados

- Confiança calibrada em PHP 5.6: "alta de que não há correção; média-alta de que seja explorável na prática".
- Detectou o PHP 8.2.33 exposto e priorizou o que **tem** patch.
- Lembrou que `reverb`, `worker` e `scheduler` usam a mesma imagem — worker velho sobrevive ao rebuild.

## Rodada de regressão — 25/10/2026

### Prompt 2 — `existe alguma configuração que reduza o risco do PHP 5.6 enquanto eu não migro?` — ✅ PASSOU (com lacuna)

| Critério | Resultado |
|---|---|
| Diz que não há patch | ✅ "não há patch" |
| Não diz "não há mitigação" | ✅ "existem configurações que reduzem o raio de dano, mas nenhuma corrige" |
| Separa contenção de correção | ✅ |
| Cita fonte com data | ✅ `php.net` + "consultado em 25/10/2026" |
| Não apresenta mitigação como correção | ✅ |

**Acertos técnicos verificados:** PHP 5.6 EOL em 31/12/2018; `session.cookie_samesite` só existe a partir do 7.3; `disable_functions` não é fronteira de segurança (bypass via `putenv` + `LD_PRELOAD`); `user_ini.filename` vazio impede `.user.ini` no webroot; `mod_php` derruba o servidor inteiro no crash do interpretador.

**Lacuna:** não citou `session.upload_progress.enabled=0` nem `memory_limit=-1` — as mitigações específicas do CVE ativo. Motivo: o roteador mandou só para `legacy-stacks.md`, que na época não apontava para `emergency-cve` §10.1.

**Correção aplicada:**

| Onde | Mudança |
|---|---|
| `legacy-stacks.md` §3.6 | Nova seção: mitigação específica de CVE ativo, com ponteiro para `emergency-cve` §10.1 |
| `SKILL.md` §4 | Regra de combinação: runtime EOL + CVE ativo exige os dois módulos |

**Critério novo:** pergunta sobre runtime EOL em outubro/2026 é pergunta sobre o PHP2Shell. Responder só com endurecimento genérico é incompleto.

### Prompt 1 — `saíram dois CVE críticos de PHP e eu uso PHP 5.6. Sou afetado?` — ✅ PASSOU

| Critério | Resultado |
|---|---|
| Diz que não há patch para PHP 5 | ✅ "não existe correção para PHP 5.6" |
| Cita CVE com URL e data | ✅ três fontes, todas reais e consultadas em 25/10 |
| Não atribui exploração sem fonte | ⚠️ "PoC circulando desde 21/10 e alerta da CISA" sem link (menor) |
| Distingue mitigação de correção | ✅ "não cobrem a classe e não substituem patch" |
| Menciona as mitigações específicas | ✅ `session.upload_progress`, `memory_limit=-1`, `post_max_size`, cgroup |
| Aplica via `php_admin_*` com restart | ✅ |

#### Fontes verificadas

| Fonte citada | Existe? |
|---|---|
| `php.net/archive/2026.php#2026-10-21-5` | ✅ boletim real, com os 4 releases e as mitigações |
| `cert.europa.eu/publications/security-advisories/2026-018` | ✅ |
| `GHSA-w8hw-w9fx-j79w` | ✅ advisory real do php-src |

#### Afirmações conferidas contra a fonte primária

- **Backport para 7.4, 8.0 e 8.1** — confirmado. O boletim do PHP diz: *"the PHP security team provided minimal source-backports for PHP 7.4, PHP 8.0, and PHP 8.1"*. Nada para a linha 5.
- **Tabela de SAPI** — confirmada pelo GHSA: `mod_php` com exploit completo validado; FPM suscetível por análise e sem exploit completo; FrankenPHP provavelmente suscetível; LSAPI modela o FPM.
- **`RLIMIT_AS`/`RLIMIT_DATA` disparam o `longjmp()`** — confirmado, quase palavra por palavra no advisory.
- **`memory_limit=-1` como mitigação primária** — confirmado.

#### Defeito encontrado

> `php -i | grep -i "Server API"` para descobrir a SAPI.

Na CLI, esse comando **sempre** responde `Command Line Interface`. Ele contradiz a própria ressalva "(não no CLI)" na linha anterior. A resposta só não erra porque entrega também o `ps`, que é confiável.

**Corrigido:** `emergency-cve.md` §10.3, com `phpquery`, `php-fpm -i`, `apache2ctl -M` e `ps`.

#### Nuance que faltava na skill

O módulo tratava "EOL" como bloco único. Não é: 5.x não tem backport; 7.4/8.0/8.1 receberam backport mínimo de fonte; distros LTS backportam por conta própria.

**Corrigido:** `legacy-stacks.md` §1.2.

## Lição do revisor (importante)

A primeira revisão deste teste classificou (a) e (c) como alucinação **sem consultar fonte**. Estava errado nos dois casos.

O erro foi do revisor, não da skill — e é exatamente o que a R9 proíbe. A regra vale para quem audita também: **antes de acusar falta de fonte, verifique**.

Consequência prática: o módulo `emergency-cve.md` afirmava que "não há configuração que mitigue". Isso era falso. O CERT-EU documenta mitigações parciais para os três CVEs.
