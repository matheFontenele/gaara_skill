## 2. Drift — alteração controlada

Para provar a detecção sem tocar em configuração real, o arquivo temporário
`/tmp/opencode/gaara-harden-app/.env` foi criado com modo `0600`, incluído no baseline
e depois alterado para `0644`:

```bash
chmod 644 /tmp/opencode/gaara-harden-app/.env

./scripts/harden_check.py \
  --now 2026-10-25T13:00:00Z \
  --host host-teste \
  --app-root /tmp/opencode/gaara-harden-app \
  --baseline /tmp/opencode/gaara-baseline.json \
  --format json > /tmp/opencode/gaara-harden-drift.json
```

Resultado:

| Campo | Antes | Depois |
|---|---:|---:|
| Score | 81 | **75** |
| Delta | — | **-6** |
| Achados altos | 2 | **3** |
| Regressões | — | **1** |
| Melhorias | — | 0 |


## 4. Invariantes verificadas

- Nenhum `sudo`; nenhuma escrita fora de `--output` e `--write-baseline`.
- Nenhuma alteração de arquivo no host durante a auditoria (teste de snapshot).
- Baseline recusa symlink e é gravado em `0600`.
- Baseline inválido retorna `1`; uso incorreto retorna `2`; achado alto/crítico retorna `3`.
- Score `null`/`insuficiente` quando a cobertura é menor que 40%.
- `--root` não avalia donos/grupos e desativa comandos do host.
- Achados seguem `references/finding-schema.md`; ação que exige aprovação tem rollback.
- Segredo não aparece na saída; `.env` foi citado apenas pelo nome e modo.

## 5. Limitações observadas nesta execução

- O host não tem servidor SSH instalado, então os controles de SSH ficaram `unknown`.
- `ufw status` não pôde ser lido sem root; a conclusão veio de `/etc/ufw/ufw.conf`.
- Não há TLS local; o controle ficou `na`.
- A detecção de Docker depende de permissão para `docker ps`/`inspect`.
- O score é heurístico e cobre apenas os controles avaliados; não é certificação.
- Drift de configuração não substitui triagem de logs ou resposta a incidente.
